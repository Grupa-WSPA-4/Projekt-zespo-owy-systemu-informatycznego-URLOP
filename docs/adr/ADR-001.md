# ADR-001
**Data:** 2026-11-04  
**Autorzy:** Zespół projektowy URLOPY Yevhenii, Mukhammed, Yauheni, Andrii, Aldiyar

## Kontekst

Zespół składa się z 5 osób pracujących w modelu hybrydowym (zajęcia stacjonarne oraz praca zdalna). Projekt realizowany jest w ramach przedmiotu akademickiego, co wiąże się z konkretnymi wymaganiami:
- Cała dokumentacja techniczna i projektowa musi być wersjonowana w centralnym repozytorium kodu.
- Wymagane jest stosowanie podejścia zorientowanego na Pull Requests (PR) z obowiązkową recenzją (code/document review) przed wdrożeniem zmian do głównej gałęzi (`main`).
- Narzędzia muszą zapewniać przejrzystość zarządzania zadaniami w całym semestrze oraz wspierać tworzenie diagramów, makiet interfejsu (UI/UX) oraz dokumentacji w formacie tekstowym (Markdown).

## Rozważane opcje

Dla poszczególnych obszarów pracy projektowej rozważono i porównano następujące opcje:

1. **Repozytorium i wersjonowanie:** GitHub vs GitLab vs Bitbucket. *(Wybór padł na GitHub ze względu na najlepszą integrację z narzędziami edukacyjnimi i projektowymi).*
2. **Zarządzanie zadaniami:** GitHub Projects / Issues vs Jira vs Trello. *(Wybór padł na GitHub Projects, aby utrzymać cały ekosystem projektu w jednym miejscu).*
3. **Dokumentacja i diagramy:** Google Docs / Confluence vs Markdown + Mermaid. *(Wybór padł na Markdown i Mermaid, co gwarantuje pełną zgodność z wymogiem trzymania dokumentacji bezpośrednio w repozytorium).*
4. **Interfejs (UI/UX):** Figma vs Adobe XD vs szkice papierowe. *(Wybór padł na Figmę ze względu na świetną współpracę w czasie rzeczywistym).*

## Decyzja

Podjęliśmy decyzję o wyborze następującego stosu narzędziowego dla projektu **URLOPY**:

| Obszar | Narzędzie | Format plików w repozytorium |
|---|---|---|
| repozytorium | GitHub | `.git` |
| zadania | GitHub Projects / Issues | Format tekstowy / powiązania w PR |
| dokumentacja | Markdown | `.md` |
| diagramy UML / BPMN | Mermaid.js / PlantUML | `.md` (skrypt Mermaid wewnątrz dokumentacji) |
| model danych | Narzędzie do modelowania relacyjnego / Mermaid ER | `.md` lub skrypty SQL `.sql` |
| interfejs | Figma | Linki w dokumentacji / pliki graficzne |
| komunikacja | Telegram / Discord | — (kanały tekstowe i głosowe) |

## Konsekwencje

### Co zyskujemy:
- **Jedno źródło prawdy (Single Source of Truth):** Cała dokumentacja, diagramy i kod znajdują się w jednym repozytorium na GitHubie.
- **Przejrzystość procesów:** Każda zmiana w dokumentacji przechodzi przez Pull Request z recenzją zespołu, co uczy dobrych praktyk inżynierskich.
- **Automatyczne renderowanie:** Diagramy zapisane jako kod Mermaid są natywnie renderowane na GitHubie bez potrzeby dołączania plików binarnych.

### Co tracimy / jakie są ryzyka:
- **Krzywa uczenia się:** Wymóg pisania całej dokumentacji w formacie Markdown oraz tworzenia diagramów w kodzie (Mermaid) może na początku zająć nieco więcej czasu niż tradycyjne edytory tekstowe typu MS Word.
- **Konflikty przy scalaniu (Merge Conflicts):** Równoczesna praca kilku osób nad tym samym plikiem Markdown może powodować konflikty w systemie Git, wymagające ręcznego rozwiązania.
